# ADR-0008: 多分支流水线用 ctx.userQuestions 弹窗增减分支

- 状态：Accepted
- 日期：2026-10-21

## 背景

多分支流水线在网页端的体验是：运行时弹窗勾选「运行分支」，再次运行可以继续添加或移除。
只靠 `cicd_run { branches: [...] }` 让模型拼分支列表，用户既看不到上次的分支集，
也不方便做「去掉一条、再加一条」。

DSH 有现成的交互提问 seam：`ctx.userQuestions`（由
`@deepseek-ai/dsh-client-ui-user-questions` 这类 client 插件注册 UI provider，
内置的 `ask_user_question` 工具就是它的消费者）。问题支持 `options` + `multiSelect` +
自由文本 `custom`。

第一版尝试「保留哪些 + 自由文本新增」两步，实测多选项不支持预选、且无选项的空问题不能提交；
第二轮改成「移除多选 + 独立新增问题」，仍然需要两步。
最终采用**单个问题**：多选列表 = 要移除的分支（不勾 = 全部保留），列表下方的输入框 = 新增分支（可留空）。

## 决策

- `cicd_run` 增加 `interactive: true`：
  1. 先读分支状态（`isBranchMode` + 上次 `CI_SOURCE_BRANCHES`）；
  2. 多分支且上次有分支时，调用 `ctx.userQuestions.ask()` 弹**一个**问题：
     - `options`（multiSelect）= 上次分支，**勾选 = 本次取消该分支**，不勾 = 保留（对齐网页端默认全选）；
     - 选项描述与标题都写明「勾选 = 取消」，降低反直觉感；
     - `custom`（输入框）= 新增分支，逗号/空格分隔，可留空（完全不动点「跳过本题」）；
     - 至少保留或新增一个分支，否则报错、不触发；
  3. 用 **`branchMode: "replace"`** 触发，提交用户确认后的最终集合——
     否则 append 会把用户刚取消的分支又加回来。
- `preview: true`：只弹窗选分支并返回结果，不触发运行（用于验证 UI / 确认分支集）。
- 服务不可用、不是多分支、或没有上次分支记录时，给出明确错误并提示改用 `branches` 参数。
- 交互结果不落盘：下一次仍以云效最新一次运行的分支集为准。

## 后果

- 用户获得与网页端一致的「加减分支」体验；模型不再需要拼分支列表。
- 依赖 client UI 注册 provider；纯命令行/无 UI 环境会报错并回退到 `branches`。
- 弹窗会阻塞工具调用，`cicd_run` 的超时从 60s 提升到 180s。
- 交互选择与手动 `branches` 完全等价，没有新增存储或状态。
