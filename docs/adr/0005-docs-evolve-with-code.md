# ADR-0005: Spec/ADR/文档随代码一起演进，并用脚本守门

- 状态：Accepted
- 日期：2026-10-21

## 背景

项目由人和模型共同修改。只写 README 的问题是：行为改了、工具参数改了，文档没人同步，
几轮之后文档就开始撒谎，模型读到旧约定还会放大错误。

成熟工程一般有三层文档：**使用说明（README）**、**规格（Spec）**、**决策记录（ADR）**。
但「写了文档」不等于「文档会跟着改」——需要机制。

## 决策

1. 建立三层文档：
   - `docs/spec/spec.md`：需求、数据模型、验收标准（当前行为的唯一事实来源）；
   - `docs/adr/NNNN-*.md`：为什么这么做，编号递增、不修改历史；
   - `docs/tools.md`：工具面参考（模型直接读）。
2. 在 `docs/README.md` 写死「改动 → 必须同步哪份文档」的映射。
3. 新增 `scripts/check-docs.mjs`，并入 `pnpm check`，检查：
   - 必需文档存在；
   - 每篇 ADR 有标题、状态、背景/决策/后果，且被索引列出；
   - `docs/tools.md` 的工具章节与代码注册的工具**完全一致**（多一个少一个都失败）；
   - 文档里的相对链接都能解析到真实文件。
4. `AGENTS.md` 把「文档和代码同一个提交」写成约定，人和模型都遵守。

## 后果

- 结构性文档漂移会在提交前失败，不依赖人记得。
- 语义漂移仍要靠评审：脚本只能保证「写了的没漏、工具没对不上」。
- 新增工具/ADR 时必须顺手改文档，短期增加一点摩擦，长期避免文档腐烂。
- `docs/tools.md` 成为工具面的可执行契约（由 CI 校验）。
