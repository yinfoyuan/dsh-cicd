# ADR-0016: 设置页改为本地配置中心

- 状态：Accepted
- 日期：2026-10-22

## 背景

设置页原来只展示通知历史；通知已经在会话头部有快捷入口。用户希望设置页管理「组织 → 流水线」的配置，
并且 token 像模型凭据一样只写不读，不再暴露 `ALI_YUNXIAO_AK` 这类环境变量名。

## 决策

- 设置页内容改为「全局配置 → 组织 → 流水线」；通知历史只保留在头部 popover。
- **组织元数据、全局 token 引用、pet/toast** 存 `$DSH_HOME/cicd-settings.json`
  （全局一份，不写项目目录；通知保留条数内部默认 200，设置页不再暴露）。
- **一个全局云效 token**：默认 credential-ref `YUNXIAO_TOKEN`，设置页通过
  `ctx.credentials.set` 写入，只显示「已配置/未配置」，任何接口不返回 token 值。
  `runner#envFor` 每次操作先解析全局 token，解析不到再回退流水线自己的 `tokenEnv`。
- **流水线仍按项目隔离**：编辑写回 `<项目>/.dsh/cicd.json`，写入前用 `config.ts` 同一套校验。
- **已知项目**由 `resolveProject` 记录到 `$DSH_HOME/cicd-projects.json`；设置页据此列出所有项目。
- 新增本地配置 API（`/dsh-cicd/config/*`）：项目/组织快照、流水线增删改、组织增删、token 设置/清除、偏好保存。
- 所有编辑只动插件本地数据，不修改云效远端。

## 后果

- 设置页可以新增/删除组织；流水线只编辑显示名称/环境/confirm 或删除，新增流水线在云效创建后由配置/skill 加入；
  token 不再暴露变量名。
- token 与组织元数据跨项目共享，流水线配置仍可随项目仓库提交；
- 现有 `tokenEnv` 保留兼容：没配置全局 token 时继续按旧方式解析；
- 设置页只列「插件用过的项目」，从未运行过插件的项目需要先在该项目里用一次工具才会出现。
