# ADR-0018: 删除 `cicd_wait`，触发后本轮结束（禁止 sleep/轮询）

- 状态：Accepted
- 日期：2026-10-23

## 背景

ADR-0014 已经把 `cicd_run` 改成后台跟踪，并把 `cicd_wait` 降级为「只查一次、不阻塞」。
但实测仍出现模型在触发后等待的情况（会话 `session-338a6667`，2026-10-23 10:30）：

- 用户：「运行测试流水线」
- 模型：`cicd_run` 触发成功 → 模型决定「I'll wait for completion (~7 min) like before」→
  执行 `pwsh Start-Sleep -Seconds 120`，对话被占住；用户随后只能「取消执行」。

关键事实：**模型没有调用 `cicd_wait`**（历史会话里一次都没有），因为它被工具描述明确要求
「不要自动调用」；它改用通用的 sleep 命令来等结果。也就是说：

1. 工具名 `cicd_wait` 与行为（只查一次、不等待）不一致，模型无法从名字判断它是不是真等待；
2. `cicd_run` 的返回文本仍写着 `cicd_wait { runId, block: true }`——`block` 参数在 ADR-0014
   就已删除，这是过期指令，等于告诉模型「存在阻塞等待模式」；
3. `cicd_run` 只说「可以继续做别的事」，没有明确「本轮到此结束、不要 sleep/轮询」；
   用户说「运行流水线」时，模型会把「运行并汇报结果」当成任务，于是用 sleep 补上等待；
4. `docs/tools.md` 仍把 `cicd_wait` 描述成「等结束（可重复调用）」，与实现相反。

## 决策

- **删除 `cicd_wait` 工具**：状态查询只保留 `cicd_status`（每次只查一次、不阻塞）。
  名字暗示等待、又与 status 重复的工具会持续制造错误示范；直接移除。
- `cicd_run` 的返回文本改为**明确的结束契约**：
  「✅ 触发完成，本轮到此结束」+ 给用户的回复模板 + 「不要用 Start-Sleep / 循环 cicd_status
  或任何方式等待结果」；同时删除 `block: true` 过期指令。
- `cicd_status` 的描述补充「只查一次，不阻塞；不要在触发后循环调用等结果」。
- 同步更新 skill、README、docs/tools.md、spec、AGENTS，并新增测试锁住：
  `cicd_run` 输出包含「本轮到此结束 / 不要等待」，且不出现 `cicd_wait` / `block`。
- 内部 `Runner.wait`（预算/退避/错误分级）继续保留给测试/未来，不通过工具暴露。

## 后果

- 工具面从 7 个减到 6 个，模型不再看到「wait」这个错误暗示；触发后的默认行为是立即回复用户。
- 后台跟踪（`RunWatcher` → toast / dsh-pet）仍是唯一的进度来源；用户之后主动问时用 `cicd_status`。
- 用户明确要求「等它跑完」时，模型也不再阻塞对话；当前机制下模型应在结束时通过 toast 告知用户，
  或由用户稍后再问。如果未来 DSH 提供「后台事件唤醒会话」的能力，应优先实现唤醒，
  而不是恢复阻塞式等待工具。
- 旧会话/旧文档里可能仍引用 `cicd_wait`；新版本调用会得到「工具不存在」，模型应改用 `cicd_status`。
