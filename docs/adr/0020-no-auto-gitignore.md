# ADR-0020: 不自动写入用户的 `.gitignore`

- 状态：Accepted
- 日期：2026-10-23

## 背景

运行记录落在 `<项目根>/.dsh/cicd-runs/`，分支选择状态落在 `.dsh/cicd-branches.json`，
两者都是本地缓存，不该进 git。

早期实现（未随任何版本发布）在写运行记录/分支选择状态时自动维护 `<项目根>/.dsh/.gitignore`：
不存在就创建，缺哪条补哪条，已有内容保留。理由是「用户不用手动改」。

但它和插件一贯的边界冲突：插件只应写自己的数据，不该在用户仓库里追加文件、更不该影响 git 行为。
实际情况也印证了这点——用户第一次触发流水线后，仓库里凭空多出一个待提交的 `.gitignore`，
用户还要自己判断它是哪来的、要不要提交。

可选方案：

1. **继续自动写**（原实现）：越过「只写自己数据」的边界，且用户无从预料。
2. **只提示不改文件**：在 `cicd_list` 输出或错误文案里提示可以加一行——仍是用户决定，无副作用。
3. **完全不参与**：插件既不写也不改，忽略与否由用户自己决定。

## 决策

- 删除 `ensureLocalIgnore()`，以及 `saveRecord()` / `saveBranchSelection()` 里的调用。
- 插件**不写、也不修改**任何 `.gitignore`（项目根的、`.dsh/` 下的都不碰）。
- `cicd-runs/`、`cicd-branches.json` 要不要忽略由用户自己决定；README 与 docs/tools.md
  给出可直接复制的示例，但不主动写进用户仓库。
- 随之取消「已有内容保留」「幂等补条目」这层逻辑，也就没有和用户现有规则冲突的可能。

## 后果

- 用户仓库不会被插件悄悄改动：跑完流水线后 `git status` 里只出现用户自己造成的变更。
- 代价：想忽略运行记录的用户要自己加两行（文档给了示例），比自动写多一步。
- 已经存在的 `.dsh/.gitignore` 不会被回滚或删除——那是用户仓库里的文件，留不留由用户决定。
- 运行记录仍照旧写到 `.dsh/cicd-runs/`；不忽略只是让它们出现在 `git status`，不影响任何功能。
